# v1.2.2 发布说明

本版本重点改进局域网模型服务的可用性与配置失败时的反馈体验。

## 用户可见变化

- 放开局域网 HTTP 模型服务配置：除本机（localhost、127.0.0.1、::1）外，现在支持通过 HTTP 访问局域网地址，包括 RFC 1918 私有段（10.*.*.*、172.16–172.31.*.*、192.168.*.*）、链路本地地址（169.254.*.*）、IPv6 ULA 与链路本地地址、IPv4-mapped 形式以及 `.local` mDNS 主机名（如 http://192.168.1.50:11434/v1、http://nas.local:8000/v1）。
- 保存或测试局域网 HTTP 配置时，扩展会按地址逐一申请主机权限，并明确提示该连接为明文 HTTP，请确认信任所在局域网。
- 模型配置弹窗新增“测试连接”按钮，无需保存即可测试草稿配置。
- 配置失败时在页面显示具体原因：无法连接模型服务（含地址、端口、服务状态检查建议）、连接超时（显示实际超时秒数）、URL 校验失败、权限未授予等，替代原先模糊的“Failed to fetch”。
- 顶部通知与弹窗提示区分成功、失败和普通信息，失败提示带无障碍 alert 标记。

## 技术改进

- 所有模型请求统一经过错误转换层，将浏览器裸 `TypeError` 转为可读的双语错误消息。
- 补充核心翻译流程、共享层（URL/请求头安全校验、历史记录）的自动化测试。
