# 1.3.3 更新说明

日期：2026-09-11

## 使用方式

“设置 → 模型服务 → 点击模型卡片 → 高级设置”新增“最大并发请求数”，默认 2，允许 1–6。旧配置自动补为 2，导入、导出和会话密钥保存方式均兼容。全文区域不增加性能参数，保持原有轻量界面。

## 实现与边界

- 同一模型配置的划词、长文本、全文翻译和连接测试共用后台调度上限。模型配置之间独立；多个配置使用同一服务账户时，仍受账户总配额限制。划词等交互请求优先于排队中的全文请求，已发出的请求不会被抢占。
- 页面端根据模型上限准备待处理段落，后台限制实际网络并发。百度始终单并发，并保留至少 1.1 秒的发起间隔；其他服务保留 100 毫秒间隔。
- 429（含百度 54003）触发整条模型队列冷却，尊重 Retry-After，按连续限流次数延长等待、将并发减半，最低为 1；成功后逐步恢复。重试仍最多 3 次，鉴权或配额致命错误停止排队任务。冷却期间取消任务不再发请求。
- 全文请求在同一页面会话内用 20 毫秒窗口合并短段落，每批最多 4 段、每段不超过 800 字符；批次总量受 2400 字符以及模型输出预算约束。不同语言、提示词、术语、格式和模型配置不混批；长段落、低输出预算及推理模式保留单段路径。
- 必应、谷歌、DeepL 使用原生数组请求；百度保留单段。大模型采用带段落 ID 的 JSON 行输出，严格检查未知、重复、缺失 ID、空结果和大小上限，按 ID 恢复对应关系。批量格式异常时清除预览并自动退回单段，本次页面会话停用合批。
- 每次补充任务时优先选择与视口相交的段落，其余按距离排序。单段流式输出以 80 毫秒节流显示；批量输出收到完整、可校验的 JSON 行即可预览，不必等整批结束。最终保留原有 HTML 白名单、行内标识校验、Shadow DOM 和浅色圆角框。
- 暂停、恢复原文、设置变更和页面导航会移除未完成预览并取消任务。批内一段变化只取消该段的接收，其他段仍可完成；全部取消时中断共享网络请求。预览不写入缓存，只有完整成功的结果才按原来的段落缓存规则持久化。
- 使用量继续归属实际模型卡片：完成次数与字符量按成功段落计，API 尝试按真实网络请求计，一次合批只算一次 API 尝试，失败与取消产生的调用也计数。隐身页面不持久化统计。

## 验证

验证覆盖并发 1／2／6、优先级、429 队列冷却、旧配置迁移、原生机器翻译批次、JSON 行增量解析、错误回退、取消单段、提前渲染、格式保留、逐段缓存复用和滚动视口优先级。浏览器使用本地模拟服务，不调用用户的真实密钥。

固定的 4 段短文本浏览器样例可合为 1 次大模型请求，并在连接结束前显示首段；这说明减少了请求开销，不代表真实模型固定提速倍数。实际速度仍取决于服务首字延迟、输出速度、配额、页面长度和模型对批量格式的支持。

验证结果：类型检查、79 项单元测试通过；33 项完整浏览器回归及新增 1 项批量异常回退用例通过（共 34 项，另复跑并发 6 用例并检查设置截图）。生产构建与 ZIP 校验通过，包内版本为 1.3.3。
