# 内置翻译与语言包预装可行性

核查日期：2026-09-14。目标是无需 API Key 或第三方翻译服务，并尝试将语言包预先放入插件。

## 结论

Chrome Translator API 可以提供本地翻译，但公开接口不支持由插件指定模型文件或导入随 ZIP 附带的语言包。因此，不能以 Chrome 内置翻译实现“语言包随插件预装”的完整要求。把文件复制到插件目录不等于安装到 Chrome 的翻译组件。

`Translator.create()` 的公开选项为源语言、目标语言、取消信号与下载监视回调，没有模型 URL、文件路径或二进制数据入口。下载和初始化由浏览器管理。首次需要准备资源时还涉及用户交互，不能承诺扩展安装后静默完成。

依据：[Chrome 官方文档](https://developer.chrome.com/docs/ai/translator-api)、[Translator API 规范及创建参数](https://webmachinelearning.github.io/translation-api/)、[Chromium 语言包安装管理接口](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/on_device_translation/installer.h)。

## 本机探测

使用 Playwright Chromium 153、全新临时配置目录，加载当前插件构建，在扩展设置页检查真实 API，未注入模拟 Translator，未调用 `create()` 或发送翻译文本。

| 项目 | 结果 |
| --- | --- |
| 扩展设置页安全上下文 | 是 |
| `Translator` 存在 | 是 |
| 日语 → 中文 | `downloadable` |
| 中文 → 日语 | `downloadable` |
| 英语 → 中文 | `downloadable` |

`downloadable` 表示还需要创建译者并由浏览器准备资源，不能据此断言指定语言包的实际安装状态；Chrome 为隐私保护会隐藏语言对下载状态。结果不是翻译成功或离线可用证明，也不代表用户安装的 Chrome。

此次测试浏览器的 Service Worker 中也暴露了 `Translator`，但未验证其创建与翻译行为；官方文档仍标注不支持 Web Workers。实现时应以目标稳定版的真实调用结果验证执行位置，不能只检查对象存在，也不能将本次预发布测试环境行为当作最低版本保证。

原始探测结果位于 `.output/acceptance/native-translator-probe.json`，不提交 Git。临时浏览器配置已清理。

## 两条互斥的实现路线

### 保留 Chrome 内置引擎，接受首次下载

1. 增加无需密钥的内置服务，旧用户保留原绑定；新安装仅在支持时提供明确的准备入口。
2. 在用户点击的扩展页面检测语言对并创建译者，显示准备进度、失败与重试。准备资源完成后验证重启浏览器及断网行为。
3. 将服务接入现有功能路由、取消机制、缓存与字符统计，隐藏大模型专属选项，不自动回退云端。
4. 对全文采用分段及可见段落优先；核实稳定版执行上下文和页面关闭后的生命周期，避免关闭弹窗后任务中断。
5. 更新数据处理说明：本地翻译文本不发送到翻译服务器，语言资源由浏览器联网准备。发布说明不得声称语言包已内置。

### 保留语言包随插件附带，采用独立本地引擎

1. 首先确定首版语言范围；结合现有需求可从中日双向开始，其他语言不能伪装成已支持。
2. 选择允许分发的翻译模型，实测中文到日文及日文到中文的质量、内存、首段时间和模型文件大小。
3. 将模型、分词器、推理运行时代码随插件一起打包，运行时只加载扩展本地资源。不能继续称其为 Chrome 内置 Translator API。
4. 在 Worker 中运行兼容的独立推理引擎，检查 WASM/WebGPU、CSP、低内存、取消及资源释放；最终离线测试必须从全新配置开始并禁用网络。
5. 与现有服务抽象和功能绑定集成，保留缓存、页面恢复、错误反馈和使用量展示。根据实际包体决定是否适合发布，不能预先承诺体积或速度。

## 当前交付状态

本次完成公开接口核查及真实浏览器能力探测。尚未变更产品默认服务、添加翻译引擎或附带语言模型，也未更新版本和重新打包。需要先确定接受首次下载，还是坚持随插件附带独立模型；两者影响依赖、安装包及运行架构，不能静默用前者替代后者。
