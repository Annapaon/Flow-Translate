# 当前工作区安全检查（2026-09-10）

范围：当前 1.3.0 工作区，包括未提交的新模块、凭据与消息处理、第三方翻译请求、全文提取与译文渲染、配置导出和隐私政策网页生成。此检查不是全量渗透测试或无漏洞证明。

## 已确认并修复

| 问题 | 触发条件与影响 | 修复 |
|---|---|---|
| 自定义凭据错误回显（中风险） | 用户使用自定义认证头，服务端在 HTTP 错误中回显其值时，原脱敏列表仅包含 API Key；明文错误在截断后再脱敏，还可能残留截断的密钥前缀。错误会展示在设置页或网页浮窗。 | 三种大模型适配器将自定义请求头值纳入脱敏；先脱敏再截断显示文本，且只接受字符串错误详情。 |
| 响应大小限制不完整（中风险） | 异常或不可信的模型服务持续发送大量小 SSE 事件时，单段缓冲区限制不能约束累计输出；HTTP 错误正文也曾被无限制读取。可能导致后台与浮窗内存占用过高。 | SSE 累计原始响应限制为 8 MiB，错误正文限制为 2 MiB；超限停止消费并取消流、释放读取器。原有单段缓冲限制保留。 |
| CSS 隐藏内容进入全文请求（中风险） | 正文内的行内节点使用 `content-visibility: hidden` 或 `visibility: collapse` 隐藏内容时，序列化未完整排除，可能将不显示的文本发送给配置的翻译服务。 | 序列化补齐两项判断，块收集补齐 `visibility: collapse`；添加包含敏感哨兵文本的排除回归测试。 |

回归测试分别覆盖自定义认证头回显与截断边界、超大错误响应、连续小事件累计超限及取消、CSS 隐藏文本排除。

## 已检查的保护措施

- 后台连接检查扩展发送者 ID；历史、删除和连接测试消息仅对扩展页面开放。
- 公开设置不包含 API Key 或自定义请求头；本地存储设置为可信扩展上下文访问。
- 翻译请求省略浏览器 Cookie，拒绝自动跟随重定向；公网 API 地址要求 HTTPS。
- 译文 HTML 使用 parse5 解析和标签白名单重建；不采信返回的 URL、事件属性或脚本标签，异常格式降级为文本。
- 默认配置导出排除 API Key 和自定义请求头；导入后重新要求数据处理同意。
- 隐私政策生成器转义 HTML，不引入外部脚本或资源。
