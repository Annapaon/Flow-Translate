# 后续功能实现路径与技术方案

> 日期：2026-09-09\
> 状态：设计基线；2026-09-09 已完成本轮代码开发，实际落地范围和仍待真实环境验收的事项见 [1.3.0 开发交付记录](RELEASE_NOTES_1.3.0.md)。本文下方保留原设计要求，不将所有可选增强或人工验收项标为已完成。\
> 基线：当前一期工作区，参见 [一期核对报告](PHASE1_REVIEW.md)。\
> 目标：保持“选择文字或网页 → 获得译文 → 继续阅读”的操作逻辑，功能按需展开。

## 1. 功能范围与界面原则

本轮规划包含此前讨论的五项轻量功能，以及新增的网页全文翻译、第三方翻译服务接入。全文翻译明确要求：**保留原文，把译文放到对应原文下方，尽可能保持原文的排版和行内格式。**

| 功能 | 用户入口 | 实现范围 |
| --- | --- | --- |
| 双向互译 | 设置页开关，开启后出现互译语言下拉框 | 中文与选定外语自动确定翻译方向，关闭后恢复原翻译设置 |
| 按选区调整输出 | 设置页可选“智能输出”，默认关闭 | 单词简短释义、短语释义、句子翻译；复用现有输出模式 |
| 重新翻译 | 划词浮窗结果区 | 绕过缓存重试，按需切换翻译服务 |
| 暂停当前网站 | Popup | 本次浏览器会话暂停、永久禁用、恢复 |
| 自定义术语 | 设置页折叠区域 | 少量源词/译词及“保留原文”，不做团队术语系统 |
| 网页全文翻译 | Popup“翻译此页” | 段落下方双语排版、进度、暂停/继续、恢复原文、失败段落重试 |
| 翻译服务接入 | 设置页现有服务管理区域 | 保留大模型，并接入百度、Microsoft Translator、Google Cloud Translation、DeepL 官方 API |

设置页继续用 React 状态、原生 CSS、Zod，不为这些功能引入大型状态或样式框架。Popup 保留常用操作；高级字段按服务能力显示；浮窗不增加常驻的功能工具栏。

本文对一期规划“首期不包含整页双语排版”的扩展只作用于后续阶段，不改变一期完成范围。PDF、图片 OCR、字幕、云端账号、聊天和背词不属于本方案。

## 3. 双向互译：配置、判定与冲突处理

### 3.1 用户交互

设置页在原“源语言/目标语言”附近增加“双向互译”开关，默认关闭。打开后显示“互译语言”，例如日语，说明“中文 ↔ 日语；其他语言默认翻译为中文”。中文为首版本固定基础语言，内部使用规范语言代码，与 UI 的中文/English 显示语言无关。

开启时隐藏或禁用原源语言和目标语言输入，但保留其值；关闭时完整恢复。首次开启应从旧目标语言中选取有效外语，旧值是中文时要求用户选定外语再生效，不能形成“中文 ↔ 中文”。Popup 显示当前规则，可快捷切换互译语言，但不另存一套配置。

| 模式 | 输入 | 实际目标 |
| --- | --- | --- |
| 原模式 | 任意语言 | 原先配置的目标语言 |
| 中文 ↔ 日语 | 中文 | 日语 |
| 中文 ↔ 日语 | 日语 | 简体中文 |
| 中文 ↔ 日语 | 可靠识别的其他语言 | 简体中文 |
| 双向模式 | 不确定、纯数字、极短词或混合语种 | 使用下述回退规则，允许本次请求手动指定方向 |

“按网站记住互译语言”列为后续可选增强，不作为首批必需界面。若实现，仅保存用户主动选择的规则，不能因访问页面自动覆盖全局配置。

### 3.2 语言解析路径

新增 `core/translation/resolve-language.ts`，由后台统一调用，划词、右键、快捷键、侧边栏共用：

1. 固定模式直接保留用户指定的源语言/目标语言语义；`auto` 源语言允许服务端检测。
2. 双向模式先使用 `browser.i18n.detectLanguage(text)` 的可靠性与候选结果；内部规范化 `zh`、`zh-CN`、`zh-TW` 等中文变体。该 API 提供 `isReliable` 和语言比例，但并不保证短词准确。[Chrome i18n 文档](https://developer.chrome.com/docs/extensions/reference/api/i18n)
3. 平假名/片假名是日语辅助证据；不能仅凭汉字就判定中文。“手紙”等全汉字短词，结合最近祖先 `lang`、页面主体语言作为弱提示。侧边栏输入不默认采用当前标签页的页面语种。
4. 仍不确定时默认目标中文并标记“方向待确认”，在结果处提供紧凑的方向切换。若用户已经指定本次方向，则其优先级最高。纯数字、URL、标识符等无可译内容直接跳过。
5. 先确定 `resolvedSourceLanguage`、`resolvedTargetLanguage`，再构建 Prompt、缓存键和服务请求。不要先让机器翻译返回，再根据检测结果翻译第二次。

初期不为了每个词额外请求云端语言检测，降低延迟及调用量；后续可按服务能力对长文本增加检测。语言判定策略带版本号，便于修正规则后失效旧缓存。

### 3.3 与全文翻译、缓存的关系

划词/侧边栏按本次文本确定方向；全文翻译按页面主要内容的语言确定一次方向，并在任务开始时冻结。日语页面在“中文 ↔ 日语”下整页译成中文，页面中已经是中文的段落跳过，不能再反向翻成日语。中文页面可整页译成日语。混合语言页面允许启动前覆盖本次目标语言，不修改全局设置。

请求开始事件携带实际源语言、目标语言和服务 ID；浮窗标题、侧边栏、历史记录均使用这份元数据。中途切换设置不改变已经发出的请求，重新翻译才采用新配置；全文任务则明确停止旧任务后重新启动，避免一页混合两种目标语言。

## 4. 其他轻量功能

### 4.1 按选区调整输出

使用本地 `Intl.Segmenter` 辅助分词，结合语种、句子边界与长度判定，不能用空格数量判断中文/日文单词。阈值为可调实现参数，先通过中英日样本验证，不宣称能准确分析所有语言。

优先级为：用户明确选定的输出模式 > 开启智能输出时的自动判定 > 默认纯翻译。单词请求简短释义，短语请求简要含义，完整句子及长段落纯翻译；复用当前 `outputMode` 与 Prompt。歧义输入退回纯翻译。全文翻译强制纯翻译，不能向网页插入解释或语法分析。

机器翻译接口通常只返回译文：智能输出不可用时在设置中说明并使用纯翻译；明确选择解释/语法模式时提示选择支持此能力的服务，不偷偷调用第二个付费服务。

### 4.2 重新翻译

浮窗在完成或失败后显示“重新翻译”；默认使用当前服务，可折叠选择其他已启用服务。动作取消旧请求、生成新 `requestId`，使用当前有效设置并设置 `cachePolicy: 'refresh'`。成功结果替换对应缓存，不追加旧流式文本；旧消息即使晚到也不能写入 UI 或历史。

该操作可能产生一次新服务调用；如果中断前已发往服务端，取消不代表服务端不计费。历史记录新请求且可标记 `retryOf`；全文仅重试失败块，不能为一个段落重新发送整页。

### 4.3 暂停当前网站

Popup 显示实际域名，提供“本次会话暂停”和“永久禁用”。会话暂停使用 `storage.session` 保存精确 hostname，作用于该域名所有标签页，浏览器关闭后失效。永久禁用复用现有黑名单/白名单逻辑，恢复时只撤销暂停或禁用来源，不破坏用户其他规则。

暂停优先于启动翻译；广播取消划词与全文请求、停止观察器并清除已注入译文。恢复后等待用户重新触发，不自动补发此前文本。白名单模式下“恢复暂停”不等同于加入白名单。

### 4.4 少量自定义术语

拟定最多 100 条；字段为源词、目标词、适用源/目标语言、保留原文。方向必须显式记录，`中文 → 日语` 规则不自动倒转应用。默认精确匹配，支持明确的英文词边界；不提供正则和复杂共享管理。

LLM 仅向 Prompt 注入当前文本实际命中的条目，明确条目为数据；不能把完整术语表加入每一个全文块。支持原生术语库的服务可后续增加专用适配，需校验语对与权限，不把不同厂商术语库视为同一种接口。

对不支持术语控制的机器翻译服务，首版明确禁用强制译词；“保留原文”仅在占位符能可靠往返并通过契约测试时启用。不得在译文中做无条件字符串替换。术语匹配结果/版本纳入缓存键。

## 5. 统一翻译服务层与数据迁移

### 5.1 数据结构草案

以下是结构方向，不是可直接替换现有类型的完整代码：

```ts
type TranslationServiceProfile =
  | { id: string; kind: 'llm'; config: ModelProfile }
  | { id: string; kind: 'baidu'; appId: string; secretRef: string }
  | { id: string; kind: 'microsoft'; region?: string; secretRef: string }
  | { id: string; kind: 'google'; apiVersion: 'v2'; secretRef: string }
  | { id: string; kind: 'deepl'; plan: 'free' | 'pro'; secretRef: string };

interface ServiceCapabilities {
  streaming: boolean;
  batch: boolean;
  structuredHtml: boolean;
  richOutput: boolean; // 解释、词汇、语法等非纯翻译输出
  glossary: 'none' | 'prompt' | 'native';
  detectLanguage: boolean;
}

interface TranslationInput {
  requestId: string;
  serviceId: string;
  sourceLanguage: string; // 规范代码，允许 auto
  targetLanguage: string;
  purpose: 'selection' | 'sidepanel' | 'page';
  format: 'text' | 'safe-html';
  segments: Array<{ id: string; text: string }>;
  cachePolicy: 'use' | 'refresh';
}
```

实际类型还需包含名称、启用状态、超时、版本、可用语言及服务限制。统一输出按 `segmentId` 返回文本/结构、检测语种和完成/失败信息；LLM 可增量返回，非流式接口返回一次完整结果，不伪造逐字流式效果。适配器拥有语言代码映射、请求单位/大小限制、错误归一化和能力声明。

新增 `core/translation/` 作为 facade/orchestrator；`core/providers/` 保留现有 LLM 实现；新增 `core/services/` 放机器翻译适配器与服务注册表。UI 面向能力而非 `if (provider === ...)` 拼接功能。

### 5.2 配置迁移

增加配置 schema 版本；旧 `modelProfiles` 迁移为 `kind: 'llm'` 的服务，保留 ID 和默认服务。互译默认关闭，智能输出默认关闭，术语为空，全文默认手动启动。分两步替换旧顶层 `model/apiKey/targetLanguage` 读取，过渡期只设一个规范化写入口，不能双向独立写新旧字段。

`shared/security.ts` 使用 discriminated union 校验不同服务配置；机器翻译不要求模型、temperature、Prompt。`shared/credentials.ts` 从“profileId → 单 Key”升级为“credentialRef → 按服务区分的凭据对象”，继续支持 local/session。非敏感 App ID/Region 可在配置中保存，Secret/API Key 不进入公有设置。导出默认剥离凭据；显式含密钥导出和旧配置导入均补迁移测试。

公有设置仅携带 UI 所需的服务名称/能力及翻译规则。后台从可信配置中取得 endpoint 和凭据，内容脚本不可指定任意转发 URL。

### 5.3 缓存、用量与调度

统一流水线：权限/暂停检查 → 有效服务及规则快照 → 方向解析 → 能力检查 → 安全序列化 → 缓存 → 分批调度 → 结果校验 → 输出/历史/用量。

缓存键包括：缓存 schema 版本、原文或安全结构摘要、服务/模型/endpoint 身份、实际语对、输出模式、格式模式、有效 Prompt/术语摘要、影响结果的服务选项。凭据不明文进入键；凭据更换可通过配置 revision 隔离。`refresh` 跳过读取但成功后更新。

当前 100 条缓存不适合全文使用：拟分开 selection/page 命名空间，全文缓存设总字节上限（初始 10 MiB、7 天 TTL、LRU 清理，待压测调整），避免一篇文章淘汰全部划词缓存。全文每段不加入普通历史，默认只记录会话统计；隐身模式继续不落历史、缓存和用量。已取消或过期的请求不得持久化。

并发按服务/凭据全局限制，划词优先于全文，初始全文并发 2、单标签页一个任务。根据服务限制下调并发、字符/字节数和数组长度，保留请求头/JSON 开销。429 尊重 `Retry-After`，网络和 5xx 有界退避；凭据错误、配额耗尽、参数错误立即停止对应队列。重试可能重复计费，不能承诺 exactly-once。

## 6. 第三方翻译服务接入

接入的是用户自己开通的官方开发者 API，不等同于免费调用翻译软件网页或复用其个人订阅。第一阶段不抓取网页、不逆向私有接口、不内置共享 Key。价格、免费额度和账户可用性不写死，设置页链接服务商当前说明。

### 6.1 服务适配路径

| 服务 | 官方接口与配置 | 协议处理 | 首批功能 |
| --- | --- | --- | --- |
| 百度翻译 | `https://fanyi-api.baidu.com/api/trans/vip/translate`；App ID、Secret | POST form；`q/from/to/appid/salt/sign`；签名为原始 UTF-8 文本参与的 `MD5(appid + q + salt + secret)`，签名后再 form 编码；处理业务错误码 | 纯文本、源语种自动检测，保守按段请求 |
| 必应对应的 Microsoft Translator | `https://api.cognitive.microsofttranslator.com/translate?api-version=3.0`；Key、按资源类型需要 Region | `Ocp-Apim-Subscription-Key`、可选/必需的 Region header；JSON 文本数组，`to` 和可选 `from` | 批量文本及 `textType=html` |
| Google Cloud Translation | 优先 Basic v2：`https://translation.googleapis.com/language/translate/v2`；API Key | `q` 数组、`source`、`target`、`format=text/html`；规范解码结果中的实体，不能直接插入 HTML | 批量文本及 HTML；Advanced v3 后置 |
| DeepL API | Free/Pro 对应 `https://api-free.deepl.com/v2/translate` / `https://api.deepl.com/v2/translate`；API Key | `Authorization: DeepL-Auth-Key …`；`text` 数组、`source_lang/target_lang`、`tag_handling=html` | 文本及 HTML；扩展后台直连先做兼容性验证 |

百度协议与签名依据：[通用文本翻译接入文档](https://api.fanyi.baidu.com/doc/23)。百度首版不通过换行拼接不同块假设一一对应；多段响应先按适配器规则合并回当前输入块。MD5 仅用于官方签名协议，Web Crypto 不提供该算法时使用经过测试的小型实现，不用于缓存或凭据加密。

Microsoft 的认证字段取决于资源类型，`textType=html` 要求完整且合法的 HTML 元素；语言代码由适配器统一转换。[认证文档](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/authentication)、[Translate 文档](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/v3/translate?tabs=url)

Google v2 支持 API Key，v3 不支持同样的 API Key 认证；因此首批用 v2，后续如需 v3 再设计 OAuth 或用户自管网关，不把服务账号私钥塞进设置页。[认证文档](https://docs.cloud.google.com/translate/docs/authentication)、[v2 Translate 文档](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate?authuser=0)

DeepL 认证及 Free/Pro 地址依据：[Access and authentication](https://developers.deepl.com/docs/getting-started/auth)；结构化内容依据：[Translate text](https://developers.deepl.com/api-reference/translate/request-translation)。官方提示普通网页浏览器请求存在 CORS 限制；扩展后台有 host permission 时与网页环境不同，是否可稳定直连必须以 Chrome/Edge 真实扩展测试为准。若直连被拒，明确报告不兼容，并提供用户自行配置的网关路径；不静默使用第三方中转，也不默认引入项目运营服务器。[DeepL CORS 说明](https://developers.deepl.com/docs/best-practices/cors-requests)、[Chrome 跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

### 6.2 设置、权限和接入验证

将现有“大模型服务”区域扩展为“翻译服务”；新增时先选类型，LLM 保留现有全部字段，机器翻译只显示自己的必要字段。连接测试使用小段固定文本并显示是一次 API 调用；错误统一为认证、权限、额度、限流、语种不支持、网络、响应格式错误，展示前脱敏。

所有网络请求在 background 中完成，按用户保存/测试服务时申请具体 HTTPS origin。复用当前动态权限方案，不扩大为永久全网 API 访问。Google Key 的 URL/query 日志、百度签名相关内容、DeepL Key 都不得进入日志或错误提示。用户自管网关沿用现有 HTTPS/本机/局域网 URL 校验，并明确正文会经过该网关。

每个服务上线前核对当前账户的可用语言、单次文本单位、总请求体、条目数、QPS 和计费规则；这些限制保存在适配器元数据，测试覆盖边界。不同服务不能共用一个假定的“5000 字符上限”。

## 7. 网页全文翻译：发现、调度与双语回填

### 7.1 交互与翻译范围

Popup 增加“翻译此页”。启动前显示当前服务、实际目标语言和待处理字符估算；用户点击即开始，无额外多层确认。任务期间显示已完成/待处理/失败数量以及“暂停、继续、恢复原文”。恢复原文取消所有剩余请求并移除译文；暂停保留已经生成的译文、停止继续发送。

默认翻译当前页面可读文本，优先可视区、随后处理当前 DOM 中其余符合条件的内容，不能只翻译首屏却宣称全文完成。滚动新增内容在本次任务启用期间增量加入；不自动滚动网页，不主动展开折叠项或抓取尚未加载的下一页。数量变化时进度使用计数，避免不真实的百分比。

首批支持普通 DOM 网页：标题、段落、列表、引用、表格单元格、图片说明和常见文本容器。跳过 script/style、隐藏/不可见内容、导航与工具条控件、按钮、input/textarea、contenteditable、密码输入、代码块、数学公式、SVG/canvas、`translate=no`/`.notranslate` 和扩展自身节点。页面全文翻译不读取用户正在编辑的表单值；用户主动划词翻译输入框仍使用现有能力。

受限浏览器页面、PDF 阅读器、跨域 iframe、封闭 Shadow DOM 首批显示支持范围，不尝试绕过限制。同源 iframe 和开放 Shadow DOM 作为独立后续子阶段，避免重复注入和跨 frame ID 混淆。虚拟列表可增量跟随可见项，但需明确其离屏内容尚未被加载。

### 7.2 DOM 分块与定位

新增 `content/page-translation/`：

- `collector.ts`：TreeWalker 扫描文本节点，按语义块和计算后的布局归属分组，不把 body 的所有文字组成一个请求；嵌套 div 只翻译叶层实际文本，混合容器按连续文本区间拆块，避免父子重复。
- `serializer.ts`：提取安全行内结构、生成 segment ID 和内容摘要。
- `controller.ts`：任务状态、视口优先级、节点版本、导航/暂停清理。
- `renderer.ts`：插入、样式映射、结果检查、恢复。
- `observer.ts`：IntersectionObserver 排序、MutationObserver 增量发现与失效。

每个块保存 `{ blockId, originalNode/Range, sourceHash, revision, insertionAnchor, renderHandle }`，引用仅存在内容脚本；后台只接收序列化数据。定位主键使用随机任务 ID + 块 ID，不能依赖会因 SPA 更新变化的 CSS selector。

提交回填前检查节点仍连接、原文摘要/revision 未变、任务仍有效。原文变化则删除旧译文并仅重排该块；原节点删除就释放引用；重复文字可复用缓存，但每个位置仍有独立 block ID。服务批量响应条数/ID 错误时不得按猜测顺序填到其他段落。

### 7.3 对应位置下方插入

原 DOM 不替换、不重建，不修改原文 `innerHTML`。使用扩展标记的译文宿主插入正常文档流，让后续原文自然向下排，不能使用 fixed/absolute 浮层模拟整页双语。

| 原文结构 | 插入策略 |
| --- | --- |
| 普通段落、标题、引用 | 在对应块后插入独立译文容器；匹配块的宽度/缩进策略 |
| 列表项 `li` | 在该项原文文本区后、嵌套子列表前插入块级译文，避免多出一枚项目符号 |
| 表格 `td/th` | 在单元格内部原文后插入，不能在 `tr` 中新增普通 div 破坏表结构 |
| 混合 inline 容器 | 在合法锚点插入 `span` 宿主并设块级显示，不能把 div 塞进 p；必要时合并为最近可安全翻译块 |
| Flex/Grid/固定高度卡片 | 优先同一布局项内部附加译文，避免新宿主变成独立网格项；无法安全放入时标记该块不支持 |

恢复时只移除由当前控制器持有的宿主，撤销扩展自己登记的临时属性；不保存整页 HTML 再覆盖恢复，否则会丢失页面运行期间的状态。原节点被站点重建时，不强行复活旧 DOM。

### 7.4 格式保持方案

“尽可能一致”的验收范围为：段落对应关系、字号、字重、字体家族回退、行高、颜色、文字方向、对齐、缩进，以及常见粗体/斜体/链接/行内代码。不同语言长度不同，不承诺相同换行、相同高度或像素级复制。

译文宿主处于 Light DOM 正常流中，内部可用 Shadow DOM 隔离网页 CSS。对宿主显式设置布局，对内部通过安全白名单复制源块排版属性/CSS 变量；不复制 class、id、事件、任意 style、position、transform、固定高度和背景图片。阴影边框等装饰按需保留，不复制交互控件。主题、窗口尺寸和相关 class/style 变化时，节流重新读取排版白名单。

行内格式采用两条受控路径：

1. HTML 能力可靠的服务：把原行内结构转成只包含 `strong/em/b/i/u/br/span` 等允许元素的最小 HTML；链接地址、行内代码等保留在本地映射，传输只含占位 ID。收到结果后由安全解析器转换成受限 AST，校验标签/占位 ID，再通过 `createElement` 和 `textContent` 重建；不直接设置服务返回的 `innerHTML`。
2. 纯文本或 LLM：优先整块翻译；LLM 可按经过测试的约定返回带 ID 的结构化 runs。对占位符遗漏/重复、非法嵌套、结构化输出失败，退回该块纯文本译文，保留块级排版，明确行内强调可能丢失。百度等纯文本服务不假定能原样保留 HTML。

链接只能采用原文已有且校验过的 http/https 等允许协议地址，不接受服务生成的新 URL；不重复原 id 或可执行属性。代码占位文本仅从本地映射恢复。以完整语义块为单位尽量保留翻译上下文，不能为了加粗样式机械逐个 TextNode 翻译，造成语序破碎。

机器返回的内容都按不可信输入处理。若使用 DOM 解析器，需要保证解析阶段也不会加载远程资源；选择不执行、不取资源的解析方式，并以恶意 img/iframe/style/url 测试验证。最终仅白名单 AST 能进入页面。

### 7.5 任务协议与 MV3 生命周期

使用独立 `page-translation` Port，消息携带 `sessionId/blockId/revision`；session 绑定可信 `sender.tab.id`、`frameId` 和页面文档标识。消息包含启动、批次、块结果、失败、暂停、恢复、取消。队列与划词共用服务限流，但拥有独立 AbortController 和状态，不能因一次划词取消整页任务。

LLM 逐块可以流式请求，但网页只在完整块通过校验后回填，避免逐 token 改写整页导致布局持续跳动；浮窗保留现有流式体验。长块按句界及服务预算拆分，按子段 ID 顺序合并后放到原块下方。

设置初始单任务处理预算，如 100,000 原文字符；超出后暂停并提供“继续处理剩余内容”，不静默截断。配合分片 DOM 扫描和有限队列，防止长页面阻塞 UI；此值是产品预算，不是厂商通用请求上限。

不能假设 Service Worker 因 Port 存在就永久运行。内容脚本保留未完成块及任务快照，断线转入“已暂停”，用户继续时重连、重新检查节点、复用已完成缓存并重发未确认块。默认不持久化整页正文；结束/导航/刷新/恢复原文时释放任务。Chrome 对后台空闲、单次执行和网络等待有生命周期限制，应按可中断任务设计。[Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

MutationObserver 忽略扩展宿主及其变化；源节点变化仅使对应块失效，异步回填检查 revision。为持续更新区域设置有界重译次数，超过预算暂停该区域，防止 DOM 变化与翻译互相触发死循环。SPA URL 变化沿用当前路由事件清理任务；同 URL 内容更新靠节点版本处理。

## 8. 实施顺序与交付边界

| 阶段 | 工作与主要文件 | 完成标准 |
| --- | --- | --- |
| A：规则与轻量操作 | `shared/types/settings`、`core/translation/resolve-language`、content/options/popup/sidepanel；互译、重译、暂停 | 旧配置不变，所有翻译入口方向一致，缓存及取消无串线 |

| C：全文核心 | collector/controller/renderer，page Port、任务队列 | 普通文章标题/段落/列表/表格原文下方展示译文，能暂停、恢复、取消、重试 |

| E：体验增强与发布 | 智能输出、少量术语、可选网站互译记忆、文档 | 按服务能力显示选项，完整回归和人工兼容性抽样完成 |

A 与 B 是共同基础；C 先接现有 LLM 和一种已验证机器翻译服务即可开发，但本轮“四家服务接入”的最终交付仍需全部完成。DeepL 直连不满足时需记录网关方案及其额外部署成本，不把该接入标成已完成。上述阶段是依赖顺序，不是工期承诺，先完成纵向原型再估算。

开发中保持每阶段可发布，不把未完成全文功能默认暴露给用户。新增模块优先复用已有 SSE、缓存和安全工具；不为保存译文重写网站，不增加独立阅读器。

### 10.2 随功能一起交付的运行保障

| 配套能力 | 行为约定 | 用户界面 |
| --- | --- | --- |
| 任务进度与部分成功 | 区分待发送、进行中、完成、跳过和失败；动态内容加入时更新计数 | Popup 显示简洁计数，不为每段添加常驻工具栏 |
| 暂停/继续 | 暂停停止新请求并中止未完成请求，保留已完成译文；未完成块转回待处理，继续时重新核对节点 | “暂停 / 继续”；提示暂停前已发送的请求仍可能计费 |
| 取消与恢复原文 | 撤销任务、取消请求、断开观察器、清空队列并移除宿主；同一操作重复执行应安全 | “恢复原文”同时承担结束任务的操作，不再增加含义重复的按钮 |
| 限流与处理预算 | 按凭据控制并发、QPS、批次大小；达到全文字符预算或动态重译预算时暂停 | 只在到达预算时显示原因及继续入口；默认值由内部管理 |
| 失败分类与局部重试 | 单块内容/结构错误允许局部失败；认证、权限或配额错误暂停该服务队列；网络/限流按有界策略处理 | “重试失败段落”；账户问题提供前往服务设置入口 |
| 生命周期与断线恢复 | 标签页关闭/导航结束任务；后台断线暂停，重连后仅处理仍有效的未完成块 | 显示“已暂停，连接中断”，由用户继续；不能无限自动重发 |
| 安全回填与降级 | 输出经结构/ID 校验与白名单重建；无法保留行内格式时退回纯文本，必要时跳过不支持的布局块 | 保留可读译文或显示跳过数量，不出现服务返回的可执行内容 |
| 任务隔离及资源释放 | 按标签页、文档、session、block revision 隔离结果；任务结束释放 Port、引用、定时器和观察器 | 内部处理，不增加设置项 |

任务状态建议统一为 `idle → running → paused/completed/failed → restored`。块状态独立记录；部分块失败不等于整页失败。暂停、恢复原文或版本失效后，晚到的结果一律忽略，不更新页面、缓存或历史。暂停与“暂停当前网站”不同：前者保留本次全文译文，后者按第 4.3 节停止站点翻译并清理译文。

### 10.3 对现有取消与持久化链路的要求

不能只在内容脚本丢弃过期消息。后台也必须在异步设置读取、缓存读取完成后、实际发送前、结果持久化前检查取消信号与任务版本，避免“界面已经关闭，但请求继续发送或结果仍写入历史”。

若缓存写入已经进入事务，须定义清晰的提交边界：提交前的取消应阻止写入；已提交的成功结果不因随后关闭 UI 而回滚。用量统计单独记录已经发生的调用，不能因取消而宣称未发生调用，也不能把中止请求当作翻译成功记录。

### 10.4 实施依赖与发布门槛

在第 8 节阶段划分中增加以下必需交付约束：

- **A 阶段**完成统一语向、访问规则和取消语义；不仅修改设置页。
- **B 阶段**完成服务能力、旧配置迁移、缓存隔离和共享调度，再让机器翻译服务进入现有划词/侧栏入口。
- **C 阶段**的全文首版必须同时具备进度、暂停/继续、恢复原文、处理预算及局部重试，不能先发布只能启动而无法结束的版本。
- **D 阶段**完成安全回填、格式降级、动态页面及后台断线回归，作为全文正式开放的门槛。
- 智能输出、自定义术语、网站互译记忆仍可按 E 阶段独立交付，不阻塞基础翻译服务；但涉及它们的能力提示不能缺失。

补充集成验收场景：同一服务下同时运行全文、划词和侧栏；全文中切换目标语言或服务；请求在设置/缓存读取期间被取消；暂停后返回迟到结果；认证失效时停止排队；后台重启后继续；全文缓存达到容量上限；升级旧配置后四类入口仍正常使用。先以本地模拟服务稳定复现，再完成真实服务及 Chrome/Edge 联调。

除“进度、暂停/继续、恢复原文、失败重试”外，以上保障优先作为内部能力完成，保持插件界面简洁。本节保留设计验收要求；实际实现与验证边界以 1.3.0 开发交付记录为准。
